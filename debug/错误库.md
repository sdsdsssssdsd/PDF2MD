## E006 · Phase 7.1：Cost-Aware Failure Memory

- **目标**：冷启动/推理分账；failure 带 ocr_seconds；document profile；top_costly_failures。
- **顺手指标**：`first_accept_attempt` / `last_accept_attempt` / `cumulative_accept_curve` / `accept_curve_auc`（为 7.2 prioritization 对照）。
- **不改**：OCR 次数、Gate、Extractor、prompt、写回策略（批前 warm 只移冷启动出 repair）。
- **根因**：Worker `recognize` 内 auto-load 未透传 `load_this_call` → O-028 式 210s 被记成 repair。
- **7.2 决策**：看 `wasted_ocr_seconds_by_class` ≥35% high+跨文档 → Extractor；否则低 yield 文档 → prioritization（只改顺序）。
- **记录日期**：2026-08-22

## E003 · Phase 5I：GUI 重启不应再付 DeepSeek 冷加载

- **目标**：Worker 生命周期与 GUI 解耦；GUI 退出不 kill daemon。
- **实现**：`DETACHED_PROCESS` spawn；`reset_deepseek_worker_client(kill_worker=False)`；`run_timings` vs `worker_lifetime` 分离。

- **可选**：`python scripts/start_deepseek_ocr_daemon.py --warmup` 登录后预热。

## E002 · DeepSeek 并非「没启动」：单式超时双重 kill → 整篇 writeback_skipped

- **现象**：MD 出现 `deepseek_writeback_skipped` / 公式提取失败；`formula_qa.json` 里 `applied_count=0`。
- **误判**：以为 lean / DeepSeek 配置被关掉。
- **实况**：`health.ok=true`，OCR 已调用；首式 `ocr_timeout:30s` 后其余 `worker_session_disabled`。
- **根因**：socket hard timeout 与 Executor ThreadPool 兜底几乎同时调用 `handle_formula_timeout` → `kill_count=2`、restart 预算一次耗尽 → `disabled`。
- **修复**：`handle_formula_timeout` 幂等去重（`formula_hard_timeout_dedup`）；文档开始仍 `begin_document_session()`。
- **记录日期**：2026-08-22

## E001 · 行间公式单行 `$$...$$` 导致 Typora `\tag` 不显示

- **现象**：MD 源码已有 `\tag{6}`，Typora 预览右侧无编号。
- **根因**：写成单行 `$$...\tag{1}$$`；Typora/MathJax 对单行 display + `\tag` 渲染不稳定。
- **正确写法**：

```markdown
$$
E\left[\left(y-\hat{f}\right)^{2}\right]=Bias^{2}+V+\varepsilon\tag{1}
$$
```

- **修复**：`build_display_block` + `normalize_display_math_multiline`；规则 `markdown-display-math-multiline.mdc`。
- **记录日期**：2026-08-22
